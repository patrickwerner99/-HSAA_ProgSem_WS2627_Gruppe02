# Sale: reduzierte Preise für einen Zeitraum

## Grobe Anforderung (Vorgabe)

> G1: Der Admin kann Produkte für einen festen Zeitraum reduzieren. Es gibt einen Sale-Bereich, und die Ersparnis
> wird angezeigt.

## UI/UX-Überlegung

* **Seiten:** Navigation „Sale“ (`/sale`), Produktliste, Detailseite, Pflegeseite (Produktformular).
* In der Liste: rotes Sale-Etikett mit Prozent, neuer Preis groß, alter Preis durchgestrichen.
  Auf der Detailseite zusätzlich „Du sparst 4,00 € (13 %) – Angebot bis 30.11.2026“.
* Der Sale-Bereich ist die normale Produktliste mit Filter `sale=true`; Suche, Kategorie und Sortierung funktionieren
  dort genauso. Zusätzliche Sortierung „Größte Ersparnis“.
* **Entscheidung:** `price` in der API ist immer der Preis, den der Kunde **heute** zahlt; `regularPrice` ist der normale
  Preis. So muss kein Client selbst rechnen, und Warenkorb, Bestellung und Sortierung nach Preis stimmen automatisch.
* Ein Sale mit Startdatum in der Zukunft wird gespeichert, ändert den Preis aber erst ab diesem Tag.
* Ohne Enddatum gilt der Sale „solange Vorrat reicht“; das nutzt die Retourenware (0026).

## User Story

Als **Admin** möchte ich Produkte für einen Zeitraum günstiger anbieten, damit ich Aktionen wie „Black Week“ machen kann.
Als **Kunde** möchte ich alle Angebote an einer Stelle sehen und erkennen, wie viel ich spare.

## Akzeptanzkriterien

### Erwartetes Verhalten

* `PUT /api/products/{id}/sale` mit `salePrice`, `from`, `until` (Admin) → 200; `DELETE …/sale` beendet ihn → 200.
* `GET /api/products?sale=true` liefert nur Produkte, deren Sale heute läuft.
* Jedes Produkt liefert `price`, `regularPrice`, `onSale`, `savingPercent`, `salePrice`, `saleFrom`, `saleUntil`.
* `sort=price-asc/desc` sortiert nach dem heutigen Preis, `sort=saving` nach Ersparnis.
* Eine Bestellung während des Sales speichert den Sale-Preis in der Position (E3).
* Die Beispieldaten enthalten vier laufende Angebote.

### Fehlerfälle

* Sale-Preis nicht kleiner als der normale Preis → **400**, Feldfehler `salePrice`.
* Ende vor dem Start oder in der Vergangenheit → **400**, Feldfehler `until`.
* Nicht Admin → **401/403**.
